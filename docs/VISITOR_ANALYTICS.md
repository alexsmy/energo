# Логирование посещений

Сайт развёрнут на GitHub Pages, приём событий — на WordPress «Energo Visits» 2.2.2:
**https://nppuast.com**. Это единственный канал. Код — `wp-plugin/energo-visits/`,
спецификация — `docs/ENERGO_VISITS_PLUGIN.md`.

## Поток данных

```
index.html → js/visits.js → POST admin-ajax.php?action=energo_visit
           → EV_Inbox → EV_Store → страница «Энерго · статистика»
```

Клиент включается только на `https://alexsmy.github.io/energo/index.html`:
локальные и IP-заходы игнорируются. Endpoint берётся из `data/visits-config.json`,
секретов в репозитории нет. Query-оверрайд endpoint удалён и запрещён тестами.
Плашка согласия не показывается — прямое решение пользователя.

## Устойчивость клиента

- Отправка через `FormData` (поле `payload`) — без предварительного запроса:
  nginx на сайте блокирует `OPTIONS`.
- Таймаут `fetch` 5 с, пачки по ≤32 КБ, `eid` для дедупликации,
  очередь исходящих событий в `localStorage` (переживает перезагрузку),
  одна активная отправка, задержка с нарастанием до 60 с. `sendBeacon` — последний шанс.

## Что собирается

| Группа | Содержание |
|---|---|
| `session` | устройство, ОС, браузер, экран, сеть, UTM, `hardId`, признак headless |
| `tab` | вкладки, время без учёта фона, глубина просмотра |
| `click` | вкладки, фильтры, карточки, маркер, ссылки |
| `search` | чипы ключевых слов и введённые запросы |
| `link` | `tel:`, `mailto:`, скачивания, внешние ссылки |
| `heartbeat` | раз в 60 с, пока вкладка видна |
| Сервер | гео по `REMOTE_ADDR`, дедуп по `event_id`, срок хранения |

Просмотр мини-карточек закупок и скролл событиями не являются. `deviceId` лежит
в `localStorage`, `sessionId` — в `sessionStorage`. IP в админке маскируется.

## Настройка и доступ

```json
{
  "enabled": true,
  "endpoint": "https://nppuast.com/wp-admin/admin-ajax.php?action=energo_visit",
  "timeoutMs": 5000
}
```

Отчёт: **https://nppuast.com/wp-admin/admin.php?page=energo-visits** — только для
`manage_options`, без публичной ссылки и PAT. Главная страница содержит KPI,
карточки устройств и сессии; детализация — внутри карточки. Есть периодический
опрос раз в 15 с. Настройки приёма (Origin, лимиты, срок хранения, Telegram) —
в закрытом блоке меню «Энерго · статистика». Telegram: уведомление о новом
устройстве и ежедневная сводка; cron `ev_daily` чистит старые события.

## Проверки

1. `node build.js` — `scripts/test-visits.js` входит в `ci-checks.js`.
2. `php -l` по файлам плагина; curl-тест дедупа — в `wp-plugin/energo-visits/README.md`.
3. Сквозной тест: в копии клиента разрешить локальный адрес и направить конфиг
   на тестовый приёмник; продакшн-конфиг не трогать.
4. Логику меняют в четырёх местах: клиент, плагин, документы и тесты.
