# Энергореестр РФ — 2026

Многофайловое веб-приложение с проверенным реестром энергогенерирующих и энергоремонтных
предприятий России: холдинги → ДЗО → филиалы → конкретные электростанции, а также ремонтные,
сервисные, машиностроительные и инжиниринговые компании.

**Онлайн:** https://alexsmy.github.io/energo/index.html · **Репозиторий:** https://github.com/alexsmy/energo

## Возможности

- **Вкладки**: «Все», «Генерация», «Ремонт и сервис», «ОЕМ и инжиниринг», «Карта».
- **Поиск** по названию, полному наименованию, ИНН, региону, адресу, станции и примечаниям.
- **Фильтры**: холдинг, регион, тип объекта, способ закупки (223-ФЗ / 44-ФЗ / конкурентные /
  прямые договоры), ЭТП, «только организации».
- **Два вида**: карточки (с группировкой по холдингам) и таблица.
- **Сортировка**: «По структуре» (иерархия из `entities.tsv`/`plants.tsv`: холдинг → ДЗО →
  филиал → станция; записи холдинга идут подряд), «По названию» (алфавит), «По региону»
  (алфавит региона, затем название). Режим «По достоверности» убран. Порядок записей
  одинаков в карточках и таблице; общая логика — `js/sort.js`.
- **Карта**: Leaflet с тремя подложками (карта OSM, спутник Esri, гибрид), кластеризация,
  круглые эмодзи-иконки по типам объектов, переключатели слоёв, краткая карточка по клику
  и переход к полной карточке. Фильтры на карте скрыты и открываются кнопкой.
- **Вкладка «Закупки»**: аудит 16 ЭТП (доступность без регистрации, публичный поиск, надёжность),
  поиск тендеров из ЕИС и коммерческих площадок по предприятиям/филиалам и ключевым словам
  (включая составные фразы с учётом словоформ), единое поле поиска с автодополнением, фильтры
  по дате, площадке и слову, карточки/таблица, дедупликация одного тендера из разных источников,
  прямые ссылки на поиск площадок. Общий список ключевых слов хранится в репозитории;
  сбор обновляется по расписанию через GitHub Actions.
- **Автообновление**: страница проверяет `version.json` и при появлении новой версии показывает
  компактное уведомление справа внизу с обратным отсчётом 10 секунд; фильтры и вид сохраняются.
- **Экспорт CSV** текущей выборки (разделитель `;`, BOM для Excel).
- **Печатная версия / PDF**: `print.html` — титул, содержание, полные карточки, станции
  таблицами, перечень ЭТП и источников.
- **Мобильная версия**: адаптивная вёрстка от 320 px, выдвижная панель фильтров, полноэкранная
  карточка, таблица превращается в карточки с подписями полей, карта на всю высоту экрана.

## Сборка и запуск

```bash
node build.js                 # data.js + registry.csv + registry.json
python -m http.server 8765    # http://127.0.0.1:8765/
```

`file://` в браузере не подходит для карты (CORS/CDN), запускайте через локальный сервер.

### PDF

## Данные

`data/entities.tsv` — по одной записи на строку, разделитель `|`, 30 полей:

```
id|parent|kind|name|full|type|activity|region|address|phone|email|site|procUrl|
inn|kpp|ogrn|ceo|contact|method|etp|capacity|status|conf|sources|notes|
chiefEngineer|chiefDesigner|procContact|procPhone|procEmail
```

- `kind`: `holding` | `company` | `plant` | `филиал`.
- `parent`: `id` родительской записи; контакты и реквизиты наследуются, если не заданы.
- `etp`: коды площадок через `;` (`GPB`, `TEK`, `ROS`, `RAD`, `B2B`, `FAB`, `AST`, `SBER`,
  `RTS`, `ZAKAZ`, `KIM`, `PORTAL_ROS`, `ETP_IRAO`, `ETP_RUSH`, `BIDZAAR`, `EIS`).
- `conf`: только `high` (поле остаётся в машиночитаемых данных, но не показывается в UI).
- `sources`: коды источников через `;` (`S1`–`S6`, расшифровка в `build.js`).
- `chiefEngineer`, `chiefDesigner`, `procContact`, `procPhone`, `procEmail` — главный инженер,
  главный конструктор, ответственный/секретарь по закупкам, телефон и e-mail закупок.
  Неподтверждённые значения: «не подтверждены». Проверять `npm run validate`.

Станции добавляются в `data/plants.gen.js` (компактный массив) и генерируются в `plants.tsv`.
Координаты: `data/geo.js` — города, привязка «станция → город», точные координаты крупных
станций; для остальных используется город с детерминированным разбросом.

## Карта

- Подложка: OpenStreetMap через CDN Leaflet 1.9.4 + Leaflet.markercluster 1.5.3.
- Без интернета карта показывает сообщение, при этом реестр, фильтры и карточки работают.
- Слои: холдинги, генерация, станции, ремонт, ОЕМ/производство.
- Иконки: ★ холдинг, ⚡ генерация, Т/ГР/ГЭ/А/С/Гео/В/Сэ — типы станций, Р — ремонт, О — ОЕМ.
- Точность: город (±2–5 км) либо фактические координаты станции; данные не являются
  навигационными.

## Закупки и аудит ЭТП

Вкладка «Закупки» состоит из двух разделов:

- **Найденные закупки** — объявления из открытых источников: ЕИС через ГосПлан API,
  агрегатор GenTender (все площадки, обход по ИНН предприятий реестра) и прямые адаптеры
  ТЭК-Торг, ЭТП ГПБ, Росэлторг. В выдачу попадают только заказчики, совпадающие с
  организациями реестра. По умолчанию показываются **действующие** закупки (дедлайн не истёк,
  статус не завершён); переключатель «Завершённые» включает архив с глубиной по дате
  (`data/tender-settings.json`, поле `archiveDepthDays`). Сбор идёт постранично — не только
  первые 10 объявлений. **Единое поле поиска** «ключевое слово или заказчик» с автодополнением:
  можно ввести слово, предприятие или сразу «турбина Затонская ТЭЦ». Словоформы учитываются
  (турбина, турбины, турбине, турбин). Фильтры: даты, площадка/источник, ключевое слово.
  Кнопка **«Найти»** перечитывает свежие данные с сервера. В карточке подсвечиваются только
  слова ключевой фразы в названии (не заказчик), показываются площадка, реальный источник
  данных и причина попадания. Один тендер из разных источников объединяется в одну запись;
  ссылка ведёт на оригинальную площадку/ЕИС. Вывод карточками или таблицей; сортировка
  по дате, названию, предприятию и цене.
- **Аудит ЭТП** — сводка по всем 16 площадкам реестра: доступность без регистрации,
  наличие публичного поиска, параметр ключевого слова, надёжность, дата и время проверки,
  замечания. Для площадок с известным шаблоном есть кнопка «Открыть поиск» с подставленным
  запросом.

Список ключевых слов **общий для всех посетителей** и лежит в `data/tender-keywords.json`
(не в localStorage). Правится из репозитория:

```bash
node scripts/keywords.js list
node scripts/keywords.js remove "турбины"
node scripts/keywords.js add "турбины"
```

Поддерживаются **составные запросы** — строка с объектом `{label, search, must}`:
`search` — опорное слово, которое уходит в API площадки, `must` — обязательные группы
слов в названии закупки (И между группами, ИЛИ внутри группы). Например:

```bash
node scripts/keywords.js add "Ремонт проточной части турбины" \
  --search=турбина --must=ремонт,проточн,част,турбин
node scripts/keywords.js add "Замена уплотнений ТВД" \
  --search=уплотнение --must=замен,уплотнен,твд,высокого/давления
```

Полная фраза проверяется локально с учётом словоформ, поэтому площадкам уходит только
одно слово — поисковый запрос; несколько фраз с одним опорным словом стоят одного сетевого
запроса. Аббревиатуры (ТВД, ЦВД, ЦНД, ПЧ, ГТУ) перечисляются явно в `must`.

Сбор и публикация:

```bash
npm run collect              # аудит ЭТП + сбор закупок из ЕИС
npm run collect -- --fixture=fixture.html --no-probe   # тест парсера без сети
npm run build                # data.js + tenders-data.js + CSV/JSON + version.json
```

В GitHub Actions workflow `.github/workflows/tenders-update.yml` запускается **раз в сутки
в 06:00 по Москве** (`0 3 * * *`) и вручную (`workflow_dispatch`). Результаты
коммитятся в `main`, GitHub Pages подхватывает их автоматически. `version.json` получает
новую версию — открытая страница сама обновляется через уже существующий механизм.

Основные источники:

- **ГосПлан API** (`https://v2test.gosplan.info`) — JSON, данные ЕИС по 44-ФЗ/223-ФЗ/615-ПП,
  поиск по ключевому слову и стадии (`stage=1` — действующие, `stage=3` — завершённые),
  без ключа и регистрации, лимит 10 запросов/мин. Полный обход по ИНН там отключён,
  чтобы не получать 429.
- **GenTender** — публичный агрегатор, охватывает все площадки; обход по ИНН предприятий
  реестра и по ключевым словам, 60 запросов/мин.
- **Прямые адаптеры** ТЭК-Торг, ЭТП ГПБ, Росэлторг — дополняют охват и уточняют площадку.
- **Резервный HTML-парсер ЕИС** — не удалялся, подключается последним; порядок задаётся
  в `settings.sourcePriority`.

При 5xx/429/таймауте есть backoff и circuit breaker. Число запросов на прогон ограничено
полем `requestBudget` в `data/tender-settings.json`; когда бюджет исчерпан, пропуск
фиксируется в журнале как `budget-exhausted`. Предыдущие данные никогда не очищаются,
при ошибке сбора сохраняются старые записи. Ошибки пишутся в статус и журнал.

Подробный журнал каждого запроса доступен по ссылке **«Журнал сбора»** внизу вкладки —
`log.html`, данные в `data/collect-log.json` (последние 30 запусков). Для каждого запроса
записаны: время (МСК), источник и текст запроса, полный URL, успех/ошибка, HTTP-код,
время отклика (включая ожидание квоты), размер ответа в байтах, сколько записей найдено
и отобрано по реестру, фаза (действующие/архив), расход бюджета (`1/400`), текст ошибки.
В шапке запуска видна сводка бюджетов по всем источникам; записи `budget-exhausted`
означают, что запрос пропущен из-за исчерпания лимита. Детальный план — `PLAN_zakupki.md`.

В выдачу попадают **только объявления, совпавшие хотя бы с одной ключевой фразой**
(настройка `requireKeyword: true` в `data/tender-settings.json`). Простая привязка заказчика
к реестру недостаточна: обход по ИНН добавлял бы всё подряд, вроде «Поставки щебня».
Ключевая фраза проверяется в названии с учётом словоформ; сверка с реестром идёт
по ИНН/названию (станции привязываются к родительскому юрлицу), поэтому медицинские,
автомобильные и сторонние заказчики тоже отсекаются. Серверные запросы идут по уточнённому
списку предприятий (`tender-enterprises.json`); автодополнение в UI работает по всем записям
реестра, а по выбранной организации можно перейти к прямому поиску на ЕИС.

## Важно

Реестр собран из открытых источников и проверен по состоянию на 21.11.2026. Контакты,
руководители и реквизиты могут меняться; перед заключением договора проверяйте их
в ЕГРЮЛ и на официальном сайте предприятия. Документ не является официальным изданием.
