# Energo Visits — плагин WordPress для статистики посещений energo

Версия **2.2.2**. Замена связки `Cloudflare Worker → Render (bot_29)`:
браузер на GitHub Pages отправляет события напрямую на WordPress `nppuast.com`,
все данные и отчёт живут на одном сервере в РФ. Публичной страницы статистики нет —
доступ только в wp-admin по `manage_options`.

Код в репозитории: `wp-plugin/energo-visits/`. Подробная документация:
`docs/VISITOR_ANALYTICS.md` и `docs/ENERGO_VISITS_PLUGIN.md` репозитория `energo`.

## Установка

1. Скопируйте папку `energo-visits` в `wp-content/plugins/` сайта `nppuast.com`.
2. Активируйте плагин. При обновлении версии WordPress показывает «Заменить текущую
   версию загруженной» — данные БД сохраняются.
3. В «Энерго · статистика» проверьте Origin/префикс страницы, при необходимости
   введите токен и chat_id Telegram (поле токена пустое = оставить сохранённый).

Endpoint трекера:

```
https://nppuast.com/wp-admin/admin-ajax.php?action=energo_visit
```

## Поток данных

- `js/visits.js` (GitHub Pages) отправляет `FormData` с полем `payload` =
  `{schema:'energo-visits-v1', page, sentAt, events[]}`. Each event has `eid`.
  `FormData` CORS-safelisted — браузер не делает preflight (OPTIONS на сайте блокируется nginx).
- `EV_CORS` разрешает точный Origin `https://alexsmy.github.io`.
- `EV_Inbox` проверяет схему, размер ≤64 КБ, префикс `page`, rate-limit по IP,
  дедуплицирует по `event_id`.
- `EV_Store` пишет в `wp_energo_ev_events`, `_devices`, `_sessions`, `_daily`, `_refs`;
  производные колонки `tab/act/seconds/max_scroll/seen_pct/is_headless` заполняются при вставке,
  поэтому агрегаты идут в SQL без `json_decode` больших выборок.
- `EV_Geo` — страна/город/провайдер по `REMOTE_ADDR`, кэш 7 дней. `X-Forwarded-For`
  учитывается только при включённой настройке `trust_proxy`.
- `EV_Range` — единый период: даты выбираются в МСК (`wp_timezone`), в SQL уходят UTC-границы.
- `EV_Cron` раз в сутки агрегирует данные, чистит старые записи и, если включено,
  отправляет Telegram-дайджест.

## Структура дашборда

Главная: компактные KPI → **карточки устройств** → сессии. Настройки и обслуживание
свернуты в `<details>` внизу. На главной сознательно нет графика, общих блоков
«что смотрели»/«последние события» и кнопок сравнения/экспорта.

Карточка устройства — основной рабочий экран:

- 4 показателя по устройству: заходы, время на сайте, действия, поиски;
- чипы: IP (по умолчанию маска), гео, провайдер, экран, сеть, язык, пояс, referrer, UTM;
- «Искал» и «Нажимал» — по этому устройству, названия карточек подставляются из справочника;
- «Вкладки этого устройства», «Открывал карточки и закупки»;
- «Сессии» только этого устройства;
- «История событий устройства» с колонками Время / Событие / Подробности / Сессия.

Обновление раз в 15 с — AJAX `ev_live_poll` с точечной подстановкой значений, без
перезагрузки страницы. Есть экспорт CSV/JSON, сортируемые таблицы, тёмная тема.

Транспорт скопирован с рабочего плагина `tvs-stats`: `wp_remote_post` на
`api.telegram.org`, JSON-тело, `disable_web_page_preview`. `sslverify` по умолчанию
выключен (как на действующем сайте) и включается настройкой «Проверять TLS Telegram».
Токен в админке не выводится; сохранённый токен не перезаписывается пустым полем.

## Проверка

```powershell
curl.exe -sS -X POST "https://nppuast.com/wp-admin/admin-ajax.php?action=energo_visit" `
  -H "Origin: https://alexsmy.github.io" `
  -F "payload=<energo-test-payload.json"
```

Ожидаемый ответ: `{"ok":true,"stored":1,"duplicates":0,...}`; повтор с тем же `eid`
даёт `stored:0, duplicates:1`. Ещё проверки: `php -l` по всем PHP-файлам,
отсутствие `Warning:` на странице, ответ `ev_live_poll` = 200, экспорт CSV = 200.

## Откат

Плагин можно деактивировать. В репозитории `energo` старые `data/visits-config.json`
и `js/visits.js` остаются в git: возврат к предыдущему коммиту снова включает
Worker/Render-канал.
