# AGENTS.md — опорный файл проекта (для продолжения в новой сессии)

Проект: **Реестр предприятий РФ 2026** (`alexsmy/energo`) — веб-приложение с реестром
предприятий России: энергетика, машиностроение, авиация, судостроение, ремонт и закупки.

Документация: `docs/PROJECT.md` — пользовательская документация (README), намеренно названная иначе, чтобы не показываться на главной странице репозитория. Короткая инструкция для пользователей — `docs/QUICKSTART.md`. **НЕ добавлять корневой `README.md`** — это сделано намеренно, чтобы документация не светилась на главной странице репозитория (для следующих сессий: не «исправлять» это). Опорный файл сессий — `AGENTS.md`, план закупок — `PLAN_zakupki.md`, план прямого парсинга — `PLAN_parsing.md`.

## Сбор закупок: архитектура v2 (21.11.2026)

- **План вместо «стрельбы»:** `node scripts/collect-tenders.js --dry-run` печатает точный план запросов без сети. По фактам: 193 запроса/день, +78 по понедельникам (полная архивная сверка), все в лимитах.
- **Охват:** 78 уникальных ИНН организаций реестра (а не 20 из ручного списка). 68 ИНН-запросов в старом прогоне давали 2013 записей и ~8 полезных; 6 keyword-запросов — 84 полезных. Поэтому приоритет отдан keyword-поиску с пагинацией до `total` (`gentenderMaxPages: 6`).
- **Инкремент:** `publish_from` считается от последнего успешного прогона минус `archiveOverlapDays: 2`, а не 30 дней. При `partial: true` — откат к полному окну (`--full-window`).
- **Архив без лишних запросов:** переход `active → archive` делается локально (прошёл deadline или запись исчезла из выдачи), отдельный архивный опрос по ИНН — только по понедельникам (`--deep-archive`).
- **Состояние:** `data/tender-inn-state.json` (по ИНН: последний успех, total, emptyStreak) и `data/tender-coverage.json` (сводка покрытия, 8-дневное окно с учётом выходных).
- **Архив снимков по образцу `cam-ufa`:** `data/archive/` не лежит в git (см. `.gitignore`). Перед деплоем `node scripts/archive.js restore` забирает прошлую публикацию Pages, после сбора `snapshot` добавляет снимок за день, `prune` удаляет старше 30 дней. Просмотр — `archive.html`.
- **Публикация артефактом:** Pages должен быть переключён на Source = GitHub Actions (сейчас у `cam-ufa` именно так). Workflow `tenders-update.yml` (cron + ручной) и `site-deploy.yml` (push) собирают `_site` и деплоят через `upload-pages-artifact`/`deploy-pages`. Триггера `push` у сбора больше нет.
- **«Новое»:** сравниваем активные записи с последним снимком архива; новые get `isNew: true` и `firstSeen`. В UI (вариант 3, выбран 21.11.2026): зелёный бейдж с точкой `#1f9c60`, фон `#f4fcf7` у карточки / `#effaf3` у строки и полоска 4 px слева. Демо — `demo-new.html`.
- **Тесты:** `node scripts/test-collect.js` (5 тестов, без сети).

## Сборка и запуск

```bash
node build.js                       # пересобрать data.js / tenders-data.js / CSV / JSON
node scripts/collect-tenders.js     # аудит ЭТП + сбор закупок из ЕИС
python -m http.server 8765 --bind 127.0.0.1
# http://127.0.0.1:8765/index.html
```

```bash
chrome --headless=new --no-pdf-header-footer --virtual-time-budget=9000 \

```

## Формат данных

`entities.tsv` (31 колонка: 25 базовых + 5 контактных + `tech`):
`id|parent|kind|name|full|type|activity|region|address|phone|email|site|procUrl|inn|kpp|ogrn|ceo|contact|method|etp|capacity|status|conf|sources|notes|chiefEngineer|chiefDesigner|procContact|procPhone|procEmail|tech`

- `kind`: `holding` | `company` | `plant` | `филиал`
- `parent`: id родителя; пустые поля наследуются в `build.js` (поле `inherited` есть в данных, но в UI больше не показывается)
- `etp`: коды через `;` (GPB, TEK, ROS, RAD, B2B, FAB, AST, SBER, RTS, ZAKAZ, KIM, PORTAL_ROS, ETP_IRAO, ETP_RUSH, BIDZAAR, EIS)
- `conf`: `high` | `medium` (low не используется)
- `sources`: S1–S6, расшифровка в `build.js`

`plants.tsv`: `id|parent|name|type|region|capacity|conf|sources|tech`

## Важные решения и причины

1. Фильтры на карте скрыты по умолчанию (`body.is-map .layout` становится одноколоночной),
   чтобы карта занимала всю ширину. Кнопка «Фильтры» открывает панель поверх карты.
2. Поиск дебаунсится на 130 мс; обновление маркеров карты отложено через `setTimeout(…, 0)`
   (на `requestAnimationFrame` нельзя полагаться в фоновых вкладках); `ResizeObserver` вместо
   таймеров; маркеры пересоздаются только при изменении видимого набора. Локальные CSS/JS
   подключены с `?v=1.9` для инвалидации кэша на GitHub Pages; при каждой публикации версию
   нужно увеличивать в `index.html` и `print.html`.
3. В таблице removed колонка «Холдинг» — она вынесена в липкую строку группы; на мобильных
   таблица превращается в карточки через `data-label`.
4. Модальное окно на десктопе — `min(80vw, 1120px)`; на мобильных — полноэкранное.
5. Типы станций на карте получили эмодзи-иконки; кластеры — круглые фиксированного размера 38/42 px.
6. Подложки: OSM (`tile.openstreetmap.org`), спутник и гибрид (`server.arcgisonline.com`, Esri).
   CDN Leaflet подключены с SRI (`integrity` + `crossorigin`); внешние Google Fonts удалены —
   шрифт берётся из системного стека (`system-ui`, `Segoe UI`, локальный Inter).
7. «наследуется» убрано из карточек; примечания очищены от неинформативных фраз.
8. ИНН/реквизиты 9 организаций остаются «средними»: O-ORGRES, O-TKZ, O-ZIO, O-AEM,
   O-ZTL, O-ELSIB, R-PROMER, R-ESE, R-IRAO-SERVICE.
9. Автообновление: `version.json` (создаётся `build.js`) проверяется при загрузке, раз в 15 минут
   и при возврате во вкладку. При смене версии снизу справа плавно появляется компактное уведомление
   с иконкой `i`, текстом «Обновление данных, страница будет перезагружена · 5 с» и маленьким
   крестиком (крестик только скрывает уведомление, перезагрузка всё равно происходит через 5 с).
   Общий механизм — `createNotice(kind, icon)` в `app.js`, стили `.notice` — для будущих типов
   уведомлений. Перед перезагрузкой состояние фильтров/вида/вкладки сохраняется и восстанавливается.
10. Безопасность: CDN Leaflet зафиксированы по версиям и защищены SRI; Google Fonts удалены;
   нет трекинга, форм и запросов к GitHub из браузера. Автор коммита — `noreply@users.noreply.github.com`,
   персональный e-mail убран из истории (`git commit --amend --reset-author` + force-push).
11. Индексирование запрещено: `<meta name="robots" content="noindex, nofollow, noarchive, nosnippet,
   noimageindex">` в `index.html` и `print.html`; в `index.html` — `referrer=strict-origin-when-cross-origin`
   (отправляется только origin — требуется тайл-серверам; в print/log/archive оставлено `no-referrer`),
   плюс `robots.txt` с `Disallow: /` для всех и основных ботов.
12. Вкладка «Закупки» изолирована от основного реестра: `app.js` в `render()` скрывает `.layout`
    и показывает `#tendersView`, не трогая состояние карты и фильтров. Логика вкладки целиком в
    `js/tenders.js`, данные — в `js/tenders-data.js` (генерируется `build.js` из JSON в `data/`).
    Список слов хранится в `data/tender-keywords.json` и правится скриптом `scripts/keywords.js`,
    а не в браузере (Pages статический). Сбор переведён на бесплатный ГосПлан API по умолчанию
    (`scripts/sources/gosplan.js`), старый HTML-парсер перенесён в `scripts/sources/eis-html.js`
    как резерв и НЕ удалён. Прямой публичный поиск остальных ЭТП недоступен из браузера
    (CORS/авторизация), поэтому для них даются ссылки-шаблоны из `data/etp-audit.json`.
    При ошибке сбора предыдущие записи не удаляются. Каждый запрос логируется в
    `data/collect-log.json` и показывается на `log.html`: адрес URL, HTTP-код, время
    (включая ожидание лимита), размер ответа в байтах, найдено/взято записей, фаза,
    расчёт бюджета источника (`2/400`), ошибка. Итог запуска содержит сводку бюджетов
    по всем источникам; записи `budget-exhausted` означают пропуск запроса из-за лимита.
    Сбор идёт постранично (до `maxPages` страниц на запрос), режим `active` отбирает действующие по дедлайну/статусу,
    режим `archive` — завершённые с `publishDateFrom` на `archiveDepthDays`. ЕИС отвечает 429 при
    частых запросах: между страницами пауза `DELAY_MS`, при 429 — повтор и остановка с фиксацией
    в статусе. Кнопка «Найти» во вкладке читает свежие `data/tenders.json` и `tenders-status.json`.
    В выдачу попадают только закупки, совпавшие хотя бы с одной ключевой фразой
    (`requireKeyword: true`): обход по ИНН enterprises даёт всё подряд, поэтому
    «Поставка щебня» отсекается ещё при сборе, а не фильтром в UI. Сверка с реестром —
    по organizationCode/ИНН и по названию (станции → родительское юрлицо), поэтому
    медицинские и сторонние организации отсекаются. `--refilter` пересопоставляет уже
    собранные записи без сети. В UI автодополнение предприятия строится по всем
    записям реестра (`TENDER_DATA.allEntities`),
    совпадающие слова подсвечиваются функцией `highlight()` в `js/tenders.js`.
13. Поиск закупок: единое поле «ключевое слово или заказчик». Словоформы считает
    `js/text-match.js` (общий модуль для Node и браузера): лёгкий русский стеммер,
    `matchesKeyword`, `queryMatches`. Составной запрос задаётся объектом
    `{label, search, must}`: в API уходит одно опорное слово `search`, а полная фраза
    проверяется локально по названию (И между группами `must`, ИЛИ внутри группы).
    Это компенсирует разную семантику площадок: GenTender и ЭТП ГПБ ищут нестрого
    (OR/полнотекстово), у ТЭК-Торга двухсловный `name` даёт мусор. Сетевые запросы
    дедуплицируются по `search`, поэтому несколько фраз с одним опорным словом стоят
    одного запроса.

    Безопасность: токен Telegram не выводится в HTML, IP в админке маскируется,
    XFF не доверяется без настройки, раздельные nonce, JSON ответа Telegram очищается.
    Тесты: `php -l` 11 файлов (php-parser), `node scripts/test-visits.js`,
    `node build.js`, curl-тест дедупа, E2E на сайте без Warning/Fatal.
    Сознательно НЕ реализовано (премиум P3): SSE, heatmap, сохранённые представления,
    command palette, AI-сводка, воронки/retention — только после отдельного согласования.

## Что осталось / риски

- Часть официальных сайтов отвечает 403/000 из-за локального TLS-прокси и Anti-DDoS
  (rosenergoatom.ru 418, gazprom/tatenergo/mosenergo 403, gpte/boges/enplus 000).
  Проверять из обычного браузера; при подтверждении обновить `site`/`procUrl` в `entities.tsv`.
- `zakupki.gov.ru` корень отдаёт 404; в данных используется рабочий путь
  `/epz/main/public/home.html`. Локальный прокси Termux дополнительно отдаёт 404 на любые
  query-строки ЕИС, поэтому парсер проверен на сохранённой выдаче (`--fixture`), а живой сбор
  должен выполняться в GitHub Actions; при ответе 404/капче старые данные сохраняются.
- Аудит ЭТП актуализирован 22.11.2026 (п. 33). РТС-тендер в нашем окружении уводит на
  Anti-DDoS/503, АСТ ГОЗ — только информационный сайт, ЕИС и АСТ не проверены встроенным
  браузером из-за TLS локального прокси. Эти нюансы описаны в полях `browser[].note`.
  Шаблоны ссылок для B2B/RTS/AST по-прежнему ведут на главную: публичного API у них нет.
- Ссылки на ЭТП и e-mail нужно периодически перепроверять (срок — 22.11.2026).
- Площадки по-разному понимают текстовый запрос: `search` у ЭТП ГПБ — полнотекстовый,
  `name` у ТЭК-Торга при двух словах отдаёт нерелевантное, GenTender ищет нестрого.
  Поэтому в API уходит только опорное слово, а составная фраза проверяется локально.
  Если площадка изменит параметр поиска, адаптер начнёт отдавать 0 записей — проверять
  по `data/collect-log.json`.
- ГосПлан отвечает 429 при частых запросах; полный обход по ИНН там отключён
  (`gosplanMaxInn: 0`), обход по ИНН делает GenTender. Включать `gosplanMaxInn` только
  с большим интервалом.
- Google AI Mode через вкладку браузера (`udm=50`) работает; websearch недоступен (402).

  цепочку по образцу cam-ufa.
