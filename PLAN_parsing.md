# Прямой парсинг площадок: статус

План выполнен и закрыт; файл описывает принятую архитектуру, а не будущие работы.

## Принцип

Запрос → встроенный JSON страницы → разрешённый перечень полей → нормализация →
дедупликация → запись. Markdown-ридеры и локальный экстрактор — только резерв,
результат их работы хранится в той же схеме.

## Реализовано

- `tektorg-direct` — POST `/api/getProcedures` (JSON) вместо тяжёлой SSR-страницы.
- `etpgpb-direct` — GET `/api/v2/procedures/` (JSON:API).
- `roseltorg-direct` — `search_ajax` с явным сообщением об изменённой разметке.
- `rad-direct` — публичный индекс лотов; `fabrikant-direct` — встроенные данные
  Next.js; `zakazrf-direct` — серверная таблица объявлений.
- Старые SSR-адаптеры (`tektorg`, `etpgpb`, `roseltorg`) доступны для A/B;
  `eis-html` остаётся крайним резервом.

При совпадении записей приоритет у прямого источника, затем у ЕИС, затем
у старых адаптеров и агрегатора: ссылка и поля площадки остаются от первоисточника.

## Проверки

```bash
npm run test:direct     # офлайн-тесты на сохранённых ответах
npm run compare:direct  # сверка выдачи до и после прямого сбора
node scripts/collect-tenders.js --dry-run
```

Фикстуры — в `prototype/fixtures/`. Ограничение частоты и задержка с нарастанием
реализованы в `scripts/lib/throttle.js`; там же проверяются редиректы и схемы URL.
